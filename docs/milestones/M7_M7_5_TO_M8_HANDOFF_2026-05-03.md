## Receipt Boundary

The first receipt type is:

```text
trust_domain: media_trust
receipt_type: content_video_receipt
receipt_status: draft | reviewed | approved_for_packet | delivered
```

The receipt documents workflow evidence only:

- declared workflow
- generated artifacts
- QA checks
- review state
- approval state
- evidence trail

It does not claim:

- universal synthetic-media detection
- identity verification
- liveness verification
- proof that manipulation did not occur outside the captured workflow
- candidate ranking
- automated hiring
- hire/no-hire recommendation
- Work Trust readiness
- customer portal readiness

Receipt lifecycle is separate from content lifecycle:

- `draft`: packet generated, not externally approved.
- `reviewed`: packet has been reviewed as evidence.
- `approved_for_packet`: packet is cleared for reviewer/demo packet use.
- `delivered`: packet was delivered/shared.

Content approval does not imply receipt approval. Receipt approval does not
imply customer delivery.
